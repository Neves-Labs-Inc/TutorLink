## Task P2-T5.1 — Real route guards and removal of the dev-only bypass

**Satisfies:** REQ-028, and discharges D-013
**Agent:** `coder-sr`
**Dependencies:** `P2-T4.1`, for the `status` field on `authStore` — the guard's three-way
decision (loading / anonymous / authenticated) cannot be written against the Phase 1 store,
which has no such field.

### Objective

Make the guards enforce the real rules, and remove every trace of the Phase 1 scaffolding
that let an unauthenticated browser into the shell.

### Files owned (exclusive writable set)

```
dashboard/src/components/layout/RouteGuard.tsx
dashboard/src/components/layout/AppShell.tsx
```

Exactly two files — the same two `01-02-PLAN.md`'s T2.3 owned when it added the bypass. Do
not touch `App.tsx` (no route changes), the stores, `Login.tsx`, `AdminSidebar.tsx`,
`TutorNav.tsx`, `index.css`, or anything under `components/ui/`.

### What to build

**1. `RouteGuard.tsx` — delete the bypass, add the loading state.**

Delete the `devNoAuth` constant and its branch at `RouteGuard.tsx:17-26` **in full**, along
with the `import.meta.env.DEV` reference and the comment block explaining it. Do not comment
it out, do not leave it behind a flag, do not keep the `accessToken` selector if nothing else
reads it. The order of checks becomes:

1. `status === 'loading'` → render a neutral, unstyled placeholder (an empty `<div>` with an
   `aria-busy` attribute is enough; this is not a design task). **Do not redirect while
   loading.** The bootstrap `POST /auth/refresh` from `P2-T4.1` is in flight during the first
   paint of every page load, and redirecting on an unresolved session bounces every
   logged-in user to `/login` on every reload — the exact bug the `status` field exists to
   prevent.
2. `role === null` → `<Navigate to="/login" replace />`.
3. `!allow.includes(role)` → `<Navigate to={role === 'admin' ? '/dashboard' : '/schedule'} replace />`.
   This is REQ-028's second half and it already works; leave the logic alone.
4. Otherwise render `children`.

**2. `AppShell.tsx` — delete the dev chrome-selection clause.**

`AppShell.tsx:18-20` currently reads
`role === 'tutor' || (import.meta.env.DEV && role === null && pathname.startsWith('/schedule'))`.
Reduce it to `const isTutor = role === 'tutor'`, remove the now-unused `useLocation` import
and the `pathname` destructure, and replace the D-013 comment with a one-line note that the
chrome follows the authenticated role.

**Everything else in the file stays byte-identical** — the flex layout, `max-w-6xl`,
`pb-[calc(5.5rem+env(safe-area-inset-bottom))]`, every class name. This is a logic deletion,
not a visual change. `AppShell` is now only ever rendered behind a guard that has already
established a non-null role, so there is no null-role case left to handle.

**Why deletion and not narrowing.** D-013 offered both. Deletion is chosen (D-019) because
its whole justification was that Phase 1 had nobody to log in as; `P2-T3.2` seeds an admin,
so the genuine login flow is now available locally and is strictly better to exercise than a
bypass. A narrowed opt-in would be a second, permanently-maintained authentication path whose
only user is a developer who could instead type a password.

## Verification

**Changed-risk surface.** The route guard is the one component in the dashboard whose failure
mode is a security failure rather than a cosmetic one, and this plan both rewrites it and
deletes the escape hatch that was deliberately built into it. The second risk is the reload
path: a guard that redirects while `status === 'loading'` logs every user out on every
refresh and will be misdiagnosed as a cookie problem.

**Static gate — no backend required:**

1. `docker compose run --rm dashboard npx tsc -b`
2. `docker compose run --rm dashboard npm run lint`
3. `docker compose run --rm dashboard npm run build`
4. **`grep -rn "import.meta.env.DEV" dashboard/src` → empty.** D-013 discharged.
5. `grep -rn "import.meta.env.DEV" dashboard/dist` → empty (it always was; kept so a
   regression cannot hide in the bundle).

**Live smoke — requires Plans 02-03 and 02-04 landed, the stack up, migrations applied, and
the admin seeded.** With `npm run dev` on 5173:

- Logged out, `http://localhost:5173/dashboard` → redirects to `/login`. **In dev, not only
  in a production build.** Before this task that URL rendered the admin shell; if it still
  does, the bypass was not removed and the task failed.
- `http://localhost:5173/schedule` logged out → redirects to `/login`.
- Log in as the seeded admin → `/dashboard` renders the admin shell with six sidebar items.
- **Reload** → still on `/dashboard`. A bounce to `/login` here is a FAIL: it means the guard
  redirected during `status === 'loading'`.
- Click Logout → lands on `/login`; the network panel shows `POST /auth/logout` → 204;
  `refresh_token` is gone from the cookie jar; navigating back to `/dashboard` redirects to
  `/login`; the browser Back button does not restore the shell.
- After that logout, replaying the old refresh token by hand
  (`curl -X POST localhost:8000/auth/refresh -H 'Content-Type: application/json' -d
  '{"refresh_token":"…"}'`) returns **401** — proving server-side revocation, not just a
  cleared client.
- At 375px on `/dashboard`: the hamburger panel opens, Logout inside it works, and the panel
  is not left open over the login page.
- Tutor role: create a tutor user (Phase 3 has the endpoint; for now insert one directly with
  `psql` using a hash from `python -c "import app.security as s; print(s.hash_password('…'))"`
  and a `tutor_id` pointing at an inserted `tutors` row). Log in as that user → lands on
  `/schedule`, sees the tutor nav, and `http://localhost:5173/dashboard` **redirects to
  `/schedule`** — REQ-028's second half. Logout is reachable at both 1280px and 375px.

**Browser tooling note.** Every live step above needs a browser, and no browser automation
tool has been available in any prior session (`STATE.md` → "REQ-010 is now a tooling
blocker"). The static gate is the hard gate and needs nothing; the live smoke is the
acceptance evidence and needs the Claude-in-Chrome extension connected or a human. Headless
CDP was ruled out by the user; do not substitute it, and do not report an unrun step as
passed.

**PASS requires:**

- **REQ-028** — unauthenticated on a protected route → `/login`; a tutor on an admin route →
  `/schedule`; a reload does not log anyone out.
- **REQ-027 / REQ-02A** — logout clears the client, returns 204, and makes the refresh token
  fail server-side afterwards.
- **D-013 discharged** — static gate step 4 is empty. A Phase 2 that closes with
  `import.meta.env.DEV` still present in `dashboard/src` is drift, regardless of everything
  else in this plan passing.
